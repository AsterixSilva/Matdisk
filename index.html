01 • Latar Belakang

Kenapa CampusRoute?

Lingkungan kampus kompleks

Banyak gedung, jalur, persimpangan, dan titik tujuan membuat orientasi di dalam kampus tidak selalu mudah.

Pengguna membutuhkan rute

Mahasiswa baru, pengunjung, atau pengguna lain perlu mengetahui jalur yang efektif menuju lokasi tertentu.

Masalah navigasi umum

Konsep navigasi digital bersifat umum dan belum secara khusus memodelkan jaringan jalur internal UNIMED sebagai graph.

Rekayasa ide

Konsep tersebut dikembangkan menjadi sistem khusus kampus dengan graph, Dijkstra, peta 3D, dan Mapping Mode.

03 • Konsep Graph

CampusRoute sebagai weighted graph

Vertex / Node

Representasi lokasi penting di lingkungan kampus.

Edge

Jalur yang menghubungkan dua lokasi.

Weight

Nilai pada edge, yaitu jarak antar lokasi.

Weighted Graph

Graph dengan bobot pada setiap jalur untuk dibandingkan oleh algoritma.

04 • Representasi

Model matematis

G = (V, E)

V adalah himpunan vertex/lokasi dan E adalah himpunan edge/jalur.

W(P) = Σ w(e)

Bobot sebuah jalur adalah jumlah bobot seluruh edge yang dilewati.

Shortest Path = min W(P)

Tujuan navigasi adalah mencari jalur dengan total bobot paling kecil.

05 • Perhitungan Jarak

Koordinat menjadi bobot

Setiap node menyimpan latitude dan longitude. Jarak dua titik dihitung dengan Haversine, lalu dipakai sebagai bobot edge.

a = sin²(Δφ / 2) + cos(φ₁) × cos(φ₂) × sin²(Δλ / 2)
c = 2 × asin(√a)
d = R × c
R = 6.371.008,8 meter

Input

Latitude dan longitude dari dua node.

Output

Jarak antar node dalam satuan meter.

06 • Algoritma

Dijkstra mencari jalur terpendek

1
Inisialisasi
Jarak awal 0. Node lain dimulai dari tak hingga (∞).
2
Pilih node terdekat
Pilih node yang belum diproses dengan jarak terkecil.
3
Relaksasi
Hitung jarak baru dan bandingkan dengan jarak lama.
4
Rekonstruksi rute
Gunakan previous untuk menelusuri tujuan kembali ke awal.
Jarak kandidat = jarak[u] + bobot(u, v)

Jika jarak kandidat < jarak[v]:
jarak[v] = jarak kandidat
previous[v] = u
07 • Contoh

Dijkstra memilih rute dengan total bobot terkecil

Jalur langsung

A → B

100 m

Jalur melalui C

A → C → B

50 + 30 = 80 m

Keputusan algoritma

80 m < 100 m, sehingga rute yang dipilih adalah A → C → B.

A
→
C
→
B
Shortest Path = 80 m

10 • Mapping Mode

Data peta dapat dikembangkan

Tambah Node

Membuat lokasi baru pada graph.

Bentuk Jalur

Control point dapat digeser untuk mengikuti bentuk jalan.

Hubungkan Junction

Persimpangan yang benar-benar dapat dilalui menjadi node graph.

Node ≠ Control Point

Control point hanya mengatur geometri visual. Ia tidak otomatis menjadi node dan tidak menambah langkah pada Dijkstra.
